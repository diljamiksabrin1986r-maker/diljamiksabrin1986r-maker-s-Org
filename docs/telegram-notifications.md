# Уведомления о заказах в Telegram

После успешного создания заказа витрина вызывает `POST /.netlify/functions/telegram-notify`.
Функция отправляет сообщение через Telegram Bot API `sendMessage`. В сообщении указаны номер
заказа, покупатель, телефон, способ получения, адрес доставки, оплата, товары и итоговая сумма.
Изображения чеков и внутренние идентификаторы не передаются.

Серверные переменные окружения:

- `TELEGRAM_BOT_TOKEN` — токен бота, полученный у BotFather.
- `TELEGRAM_CHAT_ID` — ID пользователя, группы или канала, куда отправляются уведомления.

Переменные должны быть доступны Netlify Functions в нужном контексте развёртывания.
Пользователь должен сначала начать диалог с ботом; для группы или канала бот должен быть
добавлен с правом отправлять сообщения. Значения не следует добавлять в исходники или
переменные с префиксом `VITE_`.

Тело запроса: `{ "order": { ... } }`. Поля описаны типом `OrderNotification`
в `src/utils/telegram.ts`. Функция принимает только JSON и POST, проверяет данные заказа,
отклоняет браузерные запросы с других сайтов и ограничивает обращения до 5 в минуту
на сочетание IP и домена средствами Netlify. Это публичный обработчик витрины:
проверка Origin и ограничение частоты не заменяют авторизацию и не подтверждают оплату.
Номер получателя и токен всегда берутся из серверного окружения, а не из запроса.

Ответы: `200` — Telegram принял сообщение, `400` — неверные данные,
`403` — другой источник, `405` — неподдерживаемый метод, `413` — превышен размер тела,
`415` — неверный тип содержимого, `429` — превышена частота запросов,
`502` — ошибка Telegram или тайм-аут, `503` — переменные окружения не настроены.
Ответы и журналы не содержат токена, ID получателя или исходных ошибок Telegram.

Отправка не блокирует оформление заказа. Она выполняется один раз после успешного создания
и для облачного, и для локального режима витрины. При отсутствии сети или ошибке доставки
заказ остаётся созданным; автоматической очереди и повторной отправки нет. Восстановление
соединения и открытие списка заказов не отправляют уведомления повторно.

Проверки без обращения к Telegram: `node --import tsx --test tests/telegram-notify.test.mts`.
Для локальной проверки с эмуляцией функций: `netlify dev --port 8889`.
